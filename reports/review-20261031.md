# DSH 新实现复核与回归（2026-10-31）

## 已实现与依据

- 保留 DSH 新增的 HTTP 服务、原生归档插件及共享配置 MCP 入口。
- `integrations/dsh-fishmemory/index.js`：限制 loopback origin，拒绝重定向，防止凭据和原始历史因误配外发；按 Unicode 码点截断，保留 emoji。
- `fishmemory/service.py`：连接空闲读取超时 5 秒；请求体超时 408；错误响应清理请求体时能从读取失败退出。
- `fishmemory/mcp_server.py`：移除过时的 synthetic-only 描述，保留外部证据非指令约束。
- README 修正过时的纯规格声明。设计依据 ADR-017、docs/06、docs/16；未添加 DSH 官方字段。

真实本地模型 MCP smoke：protocol=2025-11-25，单工具 memory_recall，返回 source=smoke-1，PASS。使用临时 SQLite 合成数据，未读写真实记忆库。此结果证明该简单样例与协议链路可用，不代表模糊检索准确率达标。

## 未实现与风险

- 未重启运行中 DSH/HTTP 服务，本次改动尚不保证被常驻进程加载；未重跑 DSH 界面闭环。
- 内存队列重试耗尽/溢出仍丢事件，无持久队列、来源检查点与补偿重放。
- 5 秒为 socket 空闲超时，不是完整上传总时限；并发上限、Windows token ACL 未补。
- 现有检索质量仍受 ADR-016 限制；多用户授权、敏感信息策略和生产验收未完成。
- MCP 依赖仍输出 Pydantic lifespan 前向引用警告，当前协议测试通过，未盲目升级依赖。

## 成本与下一工作包

本轮线上模型请求 0、线上输入/输出 Tokens 均 0，提示缓存不适用。本轮未形成新的本地 Tokens/端到端延迟对照报告，不能宣称性能改善；测试总耗时不是召回延迟。

下一工作包：可靠归档（持久待发送队列、来源检查点与重放），随后在 DSH 重启/服务离线场景复测；另需独立持出集检索质量评测。
