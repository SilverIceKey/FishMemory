# DSH + DeepSeek + FishMemory 界面实测（2026-10-31）

## 结论

自动归档→SQLite→新会话主模型调用 MCP→引用旧会话证据的链路可用；检索规划和证据筛选未通过准确性验收。不存在的项目也返回 found，最终由 DeepSeek 判别无关证据并回答未知，不能视作本地筛选成功。

## 环境与方法

- 用户明确要求在已打开 DSH 中用 DeepSeek 主模型测试插件；通过电脑技能操作界面。
- UI 当前模型 DeepSeek-V4.1-Flash / 1017 / High；本地记忆模型沿用已配置 Qwen3.5-0.8B。
- 开始时 127.0.0.1:8765 拒绝连接；运行 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-fishmemory.ps1` 后 healthz 正常。DSH 启动并不自动启动独立服务。
- 未改动插件配置、未直接向 SQLite 写测试行；所有测试文本经 DSH 输入和后台插件归档。未要求主模型读文件、执行命令或查看其他会话。
- 写入会话：`session-e6c82250-3df3-44ce-b634-b4686ffc1df3`，UI 标题“FishMemory 验收测试消息”。
- 读取会话：`session-88565bc8-5714-4998-8d24-437afd6e7e83`，UI 标题“测试跨会话记忆读取”。通过新建会话按钮创建，不是分支，不提供预期答案。

## 实际结果与证据

1. 写入明确标记为虚构的测试资料：青鹭1031，暗号“琥珀风铃726”，饮品“无糖乌龙茶”。主模型只回复“测试信息已收到”。`.fishmemory/ingest.jsonl` 确认用户 seq 8、助手 seq 20 均 stored。
2. 新会话请求查询项目暗号和饮品，主模型确实调用 `mcp__fishmemory__memory_recall`。
   - 查询“测试项目「青鹭1031」的验收暗号和饮品”：not_found。
   - 主模型自行改用“青鹭1031”：found，返回四条，其中只有一条是直接答案证据，另含查询自身与两条无关旧记录。
   - 最终回答两项正确，直接来源为 `dsh:session-e6c82250-3df3-44ce-b634-b4686ffc1df3:8`；主模型明确排除无关结果。跨会话读取成功，但首次召回和最小必要证据筛选失败。
3. 无记忆测试：“紫鲸8392”的暗号（未设定）。两次工具查询均 found，均返回青鹭相关条目；主模型最终明确回答未知，没有借用青鹭答案。最终回答通过，本地证据相关性与无记忆状态判定失败。

注意：助手称部分返回内容为“摘要”，实际归档契约是 text 块原文；不据此宣称实现了摘要压缩。
