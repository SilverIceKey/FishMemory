# FishMemory — 大肥鱼的跨会话长期记忆系统

> **项目状态：已有本地检索实验、HTTP 服务及 DSH/MCP 集成，尚未通过生产验收。**
>
> 当前范围与限制见 docs/14、docs/15、docs/16；文档中的初始规格状态不代表当前实现状态。

## 一句话目标

**把昂贵线上主 LLM 的记忆定位、筛选、摘要工作转移给本地超小型特化模型；SQLite 持久化完整可读历史；DSH 插件/MCP 提供统一调用。每次重置聊天上下文，都能通过长期记忆恢复必要经历。**

> 核心原则：**对话可以清零，经历不能因对话清零。模型可换，记忆可继承。**

## 总体方向

- **主模型**：通常为线上商业 API，负责推理、生成和执行；不要求访问其权重。
- **本地记忆模型**：首选官方 `Qwen/Qwen3.5-0.8B`（运行时与权重 revision 需锁定）；**默认 Non-Thinking**，负责检索意图判断、迭代检索规划、候选判定、证据压缩；不是主聊天模型，不先进行 LoRA/SFT。
- **持久化**：SQLite 原文、摘要、元数据、版本和索引。文本是最终可读的事实载体，不将个体经历写死到模型权重。
- **服务接口**：独立 HTTP API；可选 MCP Server；DSH 作为主要桥接集成，不应锁死核心服务。
- **触发**：自动预取（可开关、受上下文预算约束）＋ 主 LLM 按需 Tool Call，两者共享检索内核。
- **核心收益**：降低**线上输入 Token 和线上请求费用**，本地多轮检索可接受，但必须计入本地延迟、资源消耗与检索质量。**本地模型首选非思考模式（Non-Thinking），第一期不训练；多轮检索与 Thinking 模式是两回事。**

## 非目标

不是通过可训练权重保存全部人生；不是证明 AI 拥有意识；不是把所有聊天记录每轮注入主 LLM；不是强制每轮触发深度检索；不是一开始训练/微调新模型；不是把 SQLite 开放成任意可执行 SQL 工具。

## 交付验收的核心演示

用户在会话 A 告知一个可保留的偏好；确认入库；关闭会话并清空上下文；会话 B 使用同一个 agent/user 身份发问；本地模型读取 SQLite 的候选，向线上主模型传入少量带来源的记忆；主模型准确应用偏好。再重启服务、切换另一家主模型，行为仍成立。删除被授权的偏好后，不允许再恢复该偏好。

## 2026-10-30 规格修订（相对上一版）

- 固定推荐路径：**线上主 LLM → DSH（MCP + 原生桥接）→ FishMemory 独立服务 → 本地 Qwen3.5-0.8B（默认 Non-Thinking）→ SQLite**。
- 明确第一期**不训练**；优先验证模型的结构化计划、候选重排、误检/漏检，再根据数据选择 SFT/LoRA。
- 默认使用 **Non-Thinking + 有预算的多轮检索**；Thinking 仅作为明确可关闭的实验选项，不得默认自动升级。
- 区分两个不同能力：MCP 负责主模型按需回忆；DSH 原生事件桥接负责自动归档、按需预取以及 Session 与长期身份分离。
- 将**重置会话后仍准确记忆**列为不可协商的验收门槛；任何会话缓存、模型权重、动态提示词都不能是唯一事实来源。
- 强调成本目标是**线上实际 API 费用下降，记忆准确率不倒退**；不是让本地无限慢地计算。
- 上游官方文档引用核对时间更新到 2026-10-30，仍要求 Codex 在实际开发时锁定 commit/revision。
