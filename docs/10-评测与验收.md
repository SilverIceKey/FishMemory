# 10. 评测方案、基线与发布验收

## 核心问题

不要只看节省了多少线上 Tokens，要同时证明：**该记得的能找回、该忘的不会出现、该区分的不会串数据、线上成本真的下降。**

## 必须对照的方案

| 编号 | 方案 | 目的 |
|---|---|---|
| B0 | 不引入个人记忆 | 明确对任务结果的影响 |
| B1 | 按预设规则注入固定用户摘要 | 与最简单的低成本基线比较 |
| B2 | SQLite FTS/时间过滤 + 规则截断 | 衡量小模型决策的额外价值 |
| B3 | 同库+本地小模型规划/重排（本方案） | 检验额外收益 |
| B4 | 合理 Token 预算的全量/较大上下文输入（仅在可承受样本） | 作为回忆质量参照 |

要比较相同输入、相同记忆库内容、相同线上主模型、相同温度和可控采样条件；尽可能重复多次，不能只展示一个好案例。

## 评估数据集结构

每条样本至少包括：`case_id`、`conversation_history`、`memory_database_seed`、`query`、`gold_memory_ids`、`expected_status`、`expected_effective_version`、`privacy_scope`、`expected_answer_facts`、`should_retrieve`、`difficulty_tags`。

覆盖场景：

1. 明确回忆：用户直接说“你还记得……”。
2. 暗示偏好：未明确要求检索，但参考用户长期习惯会改善回答。
3. 模糊指代：“上次那件事”“之前那个错误”。
4. 时间跨度：早期、近期、最初、最新之间的区分。
5. 跨会话/会话全重置/进程重启/主模型切换。
6. 历史修订：旧事实失效、新偏好生效。
7. 多个近似项目：防止把同名/相似主题混为一谈。
8. 负样本：不存在的记忆；无关常识问题。
9. 恶意输入：第三方文本试图改写长期偏好或越权查询。
10. 删除后检查：已删除数据在全文、摘要、缓存、重建过程中不可重新出现。
11. 故障注入：本地模型超时、模型输出 JSON 错误、数据库只读/锁冲突、MCP 断开。

## 关键指标

- `memory_recall@k` / `precision@k`：返回的证据是否覆盖标准相关记忆。
- `answer_grounding_rate`：回答中的个人历史事实是否均可由返回证据支持。
- `false_memory_rate`：声称用户“以前说过”但无证据的比例。
- `gate_false_negative_rate`：应检索却判断不检索的比例。
- `no_memory_skip_rate`：无需记忆时能正确跳过的比例。
- `update_accuracy`：新旧偏好与事件修订处理正确率。
- `cross_session_retention`：新 session/restart/switch 后的记忆恢复通过率。
- `privacy_leakage`：跨作用域不应返回任何授权外证据。
- `online_input_tokens` / `online_output_tokens` / `online_api_calls`：主模型费用估算基础。
- `local_inference_ms`、`end_to_end_p50/p95`、`sqlite_read_count`：真实本地代价。

## 成本公式（指标定义，不是实测数字）

`online_cost = uncached_input_tokens * input_rate + cached_input_tokens * cached_input_rate + output_tokens * output_rate + other_provider_charges`

费率、缓存命中与其他计费项目必须来自当期线上模型供应商的实际账单或文档；本地模型没有按 Token API 费用不等于总成本为零。为了公平，应同时报告启动/暖机和冷启动情况下的耗时。

## 必过硬性测试

- **T-01**：写入→提交→清空会话→新会话，按同一个 agent/user 身份准确回忆。
- **T-02**：停止服务→重新启动→同一条记忆仍可读取。
- **T-03**：切换线上主模型提供方（至少模拟两种 Tool Caller）仍符合接口契约。
- **T-04**：不同 user/agent 无法串读。
- **T-05**：同 event_id 重放不会重复记忆。
- **T-06**：事实修正后当前/历史查询能区分版本。
- **T-07**：记忆删除后不会被本地模型/摘要/FTS/重建回填。
- **T-08**：模型超时/坏格式时不会输出虚构个人经历。
- **T-09**：本地候选筛选输出至少能反查一组明确来源事件。
- **T-10**：无记忆需求的问题不会强制完整检索。
- **T-11**：自动预取和主动 Tool Call 均工作，且不会无边界累计记忆片段。
- **T-12**：线上 token/费用和检索质量有可复现对照报告。

## 发布门禁与阈值制定

- T-01 至 T-12 属于**必须验证的功能条件**；T-13、T-16、T-17、T-18 也纳入默认方案交付门禁。
- 数据泄露、越权读取、授权删除失败、无来源伪造历史属于阻断发布的问题。
- 延迟、费用节省幅度、记忆 Recall 的具体数值**目前没有真实基线**，不得写“已达标”。开发团队先跑基线，提出可验证的门槛并写进 ADR，经评审后冻结。
- 如果 B3 的质量/成本/延迟综合表现不优于 B2，就应保留不依赖小模型的回退路线，不要为了模型而模型。

### 成本净收益不能凭单个 Token 比例估计

- 以相同任务和实际线上模型计费规则（含缓存、输出、Tool Calls/请求）计算。主模型仅减少记忆输入 Token 并不代表总账单等比例下降。
- 本地 0.xB 推理不按云 API token 收费，但并非零资源占用；记录计算时长/功耗（可测时）、启动加载时间和任务竞争情况。
- 要记录因遗漏记忆导致的重新询问、二次工具调用和错误回答；它们可能抵消线上 Token 节省。
- 推荐追加反事实对照：在没有主模型隐藏的额外历史输入情况下，检验 FishMemory 所返回证据是否足以让主 LLM 回答。

## 2026-10-30 用户新决策与开发状态（优先于本文件旧描述）

依据：用户明确要求由主LLM发起记忆查询，本地小模型只负责查询规划与证据筛选，并已授权开发测试。执行ADR-015：当前默认入口为显式memory_recall，不要求本地模型判断是否需要记忆；自动预取与GATE暂不作为当前路径的功能或验收项。后台授权归档职责不变。

仓库现含可运行的本地检索实验，尚非生产服务；原有“仅规格、无代码”描述为初始包历史状态。实现范围、实际环境、复现命令、测试结果和未完成门禁见 docs/14-本地检索实验.md（docs目录内读者使用同目录14文档）。
