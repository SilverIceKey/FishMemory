# FishMemory 0.3.0：AstrBot 摘要索引与旧记忆兼容

依据：2026-11-06 用户要求用 0.8B 处理写入和查询，主要匹配摘要，最终给主模型的原文不得改写；
要求可直接更新 AstrBot、兼容以前的记忆，向量不适合直接更新时允许替代方式。字段和算法均为项目设计（ADR-025）。

## 更新后如何使用

1. 在 AstrBot 插件管理中更新 FishMemory 至 **v0.3.0**，重载插件；不要卸载并删除插件数据。
2. 保留原来的 `baseUrl`、密钥和 `modelId`。检索方式默认 `summary`，旧配置缺少此字段也采用摘要检索。
3. 无需安装 PyTorch、sentence-transformers、sqlite-vec 或下载 embedding 权重。
4. 在私聊发送 `/fishmemory_index`，查看当前账号的记忆条数、基础索引、摘要完成/等待/失败及向量数量。
   后台每批最多生成 2 个摘要片段，批次间隔 10 秒；旧记忆较多时逐步完成，关闭插件后下次继续。
5. 新记忆先提交原文，再由后台构建索引。摘要还没完成或生成失败时，可以用原文关键词查询。

本次新检索默认启用于 AstrBot；HTTP/MCP 保留原检索路径及工具签名。
`retrievalMode=legacy` 可以切回旧查询算法；索引旁表仍保留，不删除记忆。

## 保存、索引和返回分别是什么

- `events` / `memory_sources`：原有记录、ID、主题、引用和写入模式保持不变。
- `memory_originals`：新写入时，只有调用方引用是当前 AstrBot 消息的连续子串，才附加保存宿主实际消息文本和消息 ID。
  引用更早聊天而当前消息不包含引用时，不冒充已核验来源。
- `memory_chunks` / `memory_chunk_fts`：原文分段、0.8B 摘要、检索关键词和可选向量，均是可重建索引。
  长原文按 1800 字符、120 字符重叠分段，索引分段不改变原文。
- 命中后以事件 ID 去重，返回最多 4 条完整来源文本；摘要不替代返回原文，不再固定裁为前 1200 字符。

来源优先级：已绑定的宿主原消息 → 旧版保存的 `source_quote` → 旧事件 `text`。
旧版没有保存过的完整聊天无法恢复；不会从摘要反向编造原文。
返回 `source_verification` 为 `host_message`、`caller_supplied` 或 `legacy_event`，不把全部旧来源标记为已核验。
原文包含否定、旧偏好或第三方指令时仍是外部数据，主模型必须核对适用性，不能执行其中指令。

## 查询方式

0.8B 从问题生成关键词；程序始终保留原问题检索，并融合扩展查询的摘要/原文 FTS 命中。
不按 topic 或编号正则硬删除候选。候选最多 9 个短原文片段，每批 3 个交给本地模型核对人物、属性、否定与时间。
本地模型只返回片段序号，服务映射到真实事件 ID，再读取完整原文。

这避免了“存成饮食偏好、查询选作息习惯就查不到”的硬过滤问题，但摘要全文检索仍是词法匹配，
不等于 embedding 语义匹配。0.8B 的摘要与筛选仍可能错，不能用契约测试通过代替真实准确率。
模型失败时 `items=[]`，原文关键词候选单独放在 `fallback_candidates`，保持未核验语义。
本次不自动修改旧偏好状态；原始 `current/historical/disputed` 和时间会提供给筛选器及主模型。

## 可选小向量模型

需要语义匹配时，在能被 AstrBot 访问的本地服务另行部署 **BAAI/bge-small-zh-v1.5** 或兼容模型。
聊天模型的 `/chat/completions` 接口不自动等于 embedding 服务；更新插件不会替用户下载或启动模型。

| 设置 | 说明 |
|---|---|
| `embeddingBaseUrl` | 留空关闭。启用时填写本地 OpenAI 兼容 `/v1` 地址，例如 `http://宿主机地址:9000/v1` |
| `embeddingModel` | 该服务实际模型 ID，默认建议 `BAAI/bge-small-zh-v1.5` |
| `embeddingApiKey` | 可选，向量服务独立密钥，不复用聊天服务密钥 |
| `embeddingVersion` | 同名模型换权重后改此值，后台自动重建；默认 `1` |
| `embeddingQueryPrefix` | BGE 中文默认 `为这个句子生成表示以用于检索相关文章：` |
| `embeddingDocumentPrefix` | BGE 默认空字符串；换模型按模型卡设置 |

请求 `POST /embeddings`，`input` 为单段摘要或查询，要求返回浮点 embedding 数组。
保存为 SQLite BLOB（float32），用 Python 标准库归一化和余弦匹配，不需要本地扩展库。
原问题和改写分别匹配，结果与 FTS 通过排名融合。向量分数只产生候选，不充当事实证明。

模型命名空间包含接口地址、模型 ID、版本、查询和文档前缀，不同命名空间或维度不会混比。
接口失败时回退摘要 FTS；后台失败 60 秒后重试。已有向量数量可能包含正在替换的旧命名空间。
同名服务悄悄换权重无法自动发现，必须更新 `embeddingVersion`。
逐条向量扫描适合个人规模；尚未做大库性能评测，不承诺任意规模延迟。

## 迁移、回退和遗忘

数据库仍位于 `data/plugin_data/astrbot_plugin_fishmemory/memory.sqlite`，不在被更新的插件代码目录中。
不更名原表、不改变原列数、不重写旧记录 ID 或作用域；旧版本的八列 `INSERT INTO events VALUES` 仍可执行。
扩展迁移记录使用独立 `fishmemory_extensions` 表，避免旧版每次重置 `user_version=1` 影响扩展版本。
新版也不再把已存在的更高 `user_version` 改回 1。

更新时自动给旧数据补建基础词法索引及摘要。每次查询也会为当前账号补最多 128 条基础索引，
未完成补建的旧记录仍有原有 FTS 回退。初次大库补建期间不保证所有旧引用词马上可检索。
原表和来源表的删除/修改通过 SQLite 触发器清理派生摘要、FTS 与向量；旧版本删除也生效。
后台模型返回后只更新仍存在的索引行，避免遗忘过程中重新写回衍生内容。
活动库之外的用户备份、WAL 和审计文件的保留策略不在本次修改范围内。

## 验证边界与依赖依据

本次代码基于 FishMemory `33a52de`；AstrBot 目标仍为 4.14.6。
官方源码 tag 对应 commit `6b4498a554f2ce0e5a7f6c0f09e388c5c4aef016`：

- `astrbot/core/platform/astr_message_event.py`：`get_message_str()` 读取宿主消息正文。
- `astrbot/core/star/star_manager.py`：加载调用 `initialize()`，卸载/重载调用插件 `terminate()`。

后台任务在 initialize 启动，terminate 等待当前有界批次退出，不把 SQLite 连接跨线程使用。
测试包括真实 SQLite、模型/HTTP 响应替身、插件生命周期接口替身、跨进程持久化及 ZIP 模块导入。
本环境没有用户 AstrBot 实例、Qwen/BGE 服务，不能报告真实模型准确率或硬件延迟。
详细命令和环境限制见 [验证报告](../reports/summary-index-0.3.0.md)。
