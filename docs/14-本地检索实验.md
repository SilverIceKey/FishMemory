# 14. 本地检索实验与运行说明（2026-10-30）

## 当前交付边界

用户已授权开发测试。本轮交付独立 Python/SQLite 检索实验、命令行入口、自动测试和合成数据评测；不是完整 WP-1 至 WP-5，也不是生产 MVP。核心不依赖 DSH。主 LLM 的调用请求由测试题模拟，没有调用线上 API。

依据：用户本次明确“查询记忆由主LLM发起，本地小模型判断查询哪部分记忆”。见 ADR-015。以下字段、算法、输出状态均为本项目实验设计，不是上游标准。

## 可运行范围

无需安装 Python 第三方依赖。仓库根目录执行：

```powershell
python -m unittest discover -s tests -v
python -m benchmarks.run
python -m fishmemory --db demo.sqlite --user demo --agent fish ingest examples/events.json
python -m fishmemory --db demo.sqlite --user demo --agent fish recall "示例项目为什么选择SQLite？"
```

`config.example.json` 指向本机已运行的 llama.cpp；密钥从文件读取，代码不保存密钥。CLI 可用 `--config` 指定另一份配置。先运行 `ingest`，结束进程，再运行 `recall`；会话 ID 不参与长期身份分区。数据库文件与日志不要提交版本控制。

实验写入事件格式：`id/session/topic/text/time/state`，状态为 current/historical/disputed。user/agent 是本地可信操作者提供的作用域，不是已实现的网络鉴权。**不要将这个 CLI 直接包装成无鉴权公网接口。**

## 实现与算法

- `fishmemory/core.py`：事务落盘、幂等、FTS5、身份过滤、有限动作规划、候选筛选、证据原文返回。中文采用实验性双字切片后交给 FTS5，不是语义检索或自然分词。
- `fishmemory/__main__.py`：独立进程可调用的 CLI。
- `tests/test_core.py`：自动化存储、权限边界、锁等待、模型错误和轮次预算测试。
- `benchmarks/run.py`：14 条合成历史、12 条请求；先冻结本轮题目与提示再运行，未用这些题目训练模型。规模小，不是独立持出质量认证。

服务编排最多3轮，默认2轮；每轮最多8个候选，每段原文最多1200字符，模型最多选4个ID。状态目录最多32个主题。主模型已经要求检索，流程不存在skip门控。topic/keywords/historical由本地模型提出，作用域不由模型指定。候选不足时允许重规划；模型故障仅给出标记为未核验的规则候选，不作为已确认记忆返回。

输出 `items` 为直接来源文本而非自由摘要；`found` 目前仅表示模型选中了证据，不保证其内容足以支持答案。`not_found` 仅表示预算内未选到，不证明整个库无记录。原文裁剪、目录分页、按Token返回预算、更多时间过滤均尚未完成。

## 实测结果

完整结果：`reports/retrieval-baseline.json`，包含问题、标准ID、查询计划、候选ID、选中原文、每次推理用量与时延。

| 指标 | 结果 |
|---|---:|
| 完整链路证据集合完全正确 | 5/12 |
| 给定正确证据与干扰项后的筛选完全正确 | 4/12 |
| 模型规划候选覆盖全部标准证据（有答案题） | 4/10 |
| 原始查询直接规则/FTS候选覆盖（有答案题） | 10/10 |
| 本地模型请求次数（含独立筛选对照） | 36 |
| 本地输入/输出Token | 7117 / 644 |
| 完整检索调用墙钟中位数 | 882.5ms |
| 线上输入/输出Token、请求次数 | 0 / 0 / 0 |

两道无答案题在完整链路中正确返回空，但给定含注入文本的候选时选择失败，不能宣称已防御提示注入。规则基线的10/10是候选覆盖，不是最终答案准确率，不能直接与5/12作同口径比较。没有测真实主模型使用证据后的答案，也没有真实线上成本A/B。延迟含当前运行环境与缓存影响，不是硬件SLA。

另外已实跑上述两个CLI命令：第一个进程写入demo-1后退出，第二个进程通过模型规划与筛选返回demo-1原文，耗时1141ms；这两次本地模型调用不包含在表中36次评测调用内。本演示验证跨进程读取，不等于真实DSH会话重置验收。

结论：当前0.8B+提示/运行配置尚不适合作为唯一规划器或选证据器。候选主题硬过滤会导致丢失，已召回候选的筛选也有错误。下一工作包应在新持出题上验证宽召回、弱化主题硬过滤、逐条相关性判定与确定性时间规则；不能直接据此断言模型本身不可用，也不应立刻微调。
