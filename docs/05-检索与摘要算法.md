# 05. 本地 0.xB 模型：记忆需求判断、迭代检索、摘要

> 这里设计的是独立记忆**思考/检索模型**，不需要把所有事实写到模型参数内。模型可以多轮推理，但必须预算化、可观测和可回退。

## 输入和输出

输入：当前用户请求、允许传入的短期上下文、稳定 agent/user 身份、少量记忆库状态索引，以及调用模式（自动预取 / 主模型主动回忆）。

输出：`no_memory_needed`、`found`、`partial`、`not_found`、`error` 等状态；证据条目 ID、当前有效性、简短可读内容、来源时间；可选进一步检索建议。

主模型收到的是证据，不是本地模型自由发挥的一段“回忆故事”。

## 检索状态机

1. `GATE`：当前任务是否需要个人记忆？必要时可由规则快速判定，减少每条消息都跑本地小模型。
2. `PLAN`：本地模型从问题提炼主题、时间、人物、项目、模糊指代、检索线索和预算。
3. `STATE`：读取有限的活跃主题/时间范围目录，让模型知道可检索内容所在区域。
4. `CANDIDATE`：对关键词、时间、标签、全文索引进行受控召回；产生候选 ID / 极短摘要。
5. `REFINE`：小模型判断候选是否足够、是否需要换关键词、是否需要时间线或详情；在轮次预算内多次执行。
6. `DETAIL`：按 ID 展开部分原文，核对来源与内容，识别冲突及过期信息。
7. `COMPOSE`：生成紧凑的、带来源证据的结果；严格控制线上 Token。
8. `STOP`：达到证据充分、确定无结果、轮次/时延/Token 预算任一限制即停止。

## 模型允许提出的动作（拟定内部契约）

- `skip`：无必要记忆。
- `search_topics`：在限定范围读取少量主题目录。
- `search_summaries`：按词、时间、身份等匹配候选摘要。
- `search_timeline`：围绕事件 ID 或时间窗口定位。
- `get_details`：展开选定的候选正文片段。
- `finish`：结束，给出所选证据与状态。

**这些是项目内部动作，不是 MCP 官方 Tools。** 任何超出 allowlist 的动作、非法 JSON、越权 ID，均不能执行。

## 召回与重排

建议先使用 SQLite 条件检索 + FTS5 的候选召回，再用小模型对候选的语义相关性、时效性、来源充分性重排。若评测证明无法覆盖同义/模糊表达，再引入嵌入索引，而不是无数据提前堆技术栈。

- 优先处理明确用户修改过的当前偏好，不应让旧记录在相似度上盖过新记录。
- 对“最早/当初/上次”应支持事件发生时间与会话顺序，而非按导入时间猜测。
- 对“我们以前是否讨论过”要检索证据，而不是把“看起来相似”的项目当同一项目。
- 对“上次那个错误”可使用最近上下文帮助指代消解，但不可随意跨用户检索。

## 紧凑返回原则

- 默认只返回 `memory_id`、时间、摘要、来源和适用状态。
- 只有主模型需确切引用或进行细节推断时才补充具体原文片段。
- 摘要必须可在存储中定位并核验；不可将本地模型推断包装成用户明确说过的话。
- 预算按请求独立配置：`max_iterations`、`max_candidates`、`max_detail_bytes`、`max_return_tokens`、`deadline_ms`。初始数值是建议，后续通过真实测量锁定。
- 超限时返回 partial/not_found 等结构化状态，不能静默编造完整回忆。

## 降级策略

本地模型不可用、模型响应非结构化、上下文格式异常、JSON 参数不合法、超时、结果无来源：

1. 对关键词明确的问题可退回受控 FTS/时间检索。
2. 仍无证据返回 `not_found` / `partial`，向主模型声明不可确认。
3. 不中断与记忆无关的主模型工作。

## 训练路线（不是一期必需）

一期优先使用现成小模型的结构化推理；生成有标注的记忆需求数据集（查询 → 预期相关 ID/是否应检索）；若准确率与代价不合格，蒸馏专门的检索规划器。评测改善可重复之前，不引入 LoRA 持续微调。


## Non-Thinking 与多轮检索的正式决策（ADR-009）

**一期强制默认：本地 Qwen3.5-0.8B Non-Thinking + Orchestrator 多轮检索。**

- 多轮不代表一次生成一段长思维链。每轮只接收少量状态与候选，输出**受 schema 约束的短动作**；查询执行与停止判定由受控代码负责。
- **不要**把 `enable_thinking=True` 作为模糊检索失败后的自动补救。首先检查候选召回、中文分词、实体线索和时间过滤，然后看小模型重排是否正确。
- 实验性 Thinking 必须是显式配置，记录模型 revision、后端、输出长度、超时和异常循环检测。它可能使 0.8B 产生循环、延迟过高、无法结构化结束。
- 模型输出的自然语言解释不是证据。最终摘要应仅使用允许展开且经来源核验的事件片段。

### 三条对照路径

| 对照 | Thinking | 检索流程 | 目的 |
|---|---|---|---|
| A | 无模型 | FTS/时间/规则 | 最小成本基线 |
| B（默认） | 关 | 小模型多轮受控检索 | 检验本地推理的净收益 |
| C（实验） | 开 | 与 B 相同预算条件 | 验证 Thinking 是否值得启用 |

### 预设护栏（可配置，不是实测 SLA）

- 普通检索：`max_iterations=3`，复杂回忆：`max_iterations=6`，每轮动作至多 1 个或有限个；完成的最终轮次计算规则需实现时明确。
- 线上记忆片段起始预算 `max_return_tokens=512`；必要的明确回忆允许按身份授权扩容，而不是强制摘要掩盖缺失事实。
- 限制输入候选数量、详情片段字符数、单次生成 Token、整体 `deadline_ms`；本地超时必须返回结构化降级，不允许无限重试。
- 使用当前选定的 tokenizer 计算/估计 Token，不能用字符数代替并声称精确节省。

## 是否训练：以评测驱动而不是预设

1. **一期：零训练**（官方预训练/后训练权重），固化提示模板、动作 schema、运行时与模型版本。
2. **二期评测**：若中文查询/模糊指代主要由于 FTS 检索漏召回，应先修索引；若候选齐备但小模型排序、动作选择频繁错误，考虑 SFT/LoRA 或更强小模型。
3. **训练门槛**：先建立训练/验证/独立测试集，避免训练集中出现原始评测答案；训练后报告提升与回归、部署资源、格式错误率和延迟。
4. **禁止**通过把用户大量隐私经历烘焙进权重来做增量记忆，避免无法修正和删除。
