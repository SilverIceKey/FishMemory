# 03. 总体架构、调用边界与故障隔离

## 逻辑架构

用户 / 线上主 LLM（可换）
↕ DSH 插件（自动预取 + 工具注册）/ 其他宿主 MCP Client
↕ 独立 Memory API / MCP Server
↕ Memory Orchestrator（决定是否检索、上下文预算、编排轮次）
↕ 本地 Memory Planner（0.xB Qwen 类模型，结构化动作）
↕ 安全 Query Executor + SQLite（事件原文、派生摘要、主题状态索引、FTS）

**生命周期真值源是 SQLite，而不是 DSH Session、主 LLM 上下文或本地模型权重。**

## 模块职责

| 组件 | 应做 | 不应做 |
|---|---|---|
| 主 LLM | 最终推理和面向用户响应 | 承担大规模历史扫描 |
| DSH 适配器 | 发现需要预取的时机、注册工具、捕获允许的会话事件 | 保存唯一持久记忆或绑定 SQLite 模式 |
| MCP 适配器 | 工具发现/调用/结果转换 | 执行记忆检索业务逻辑 |
| Memory API | 鉴权、预算、幂等和输入输出契约 | 泄露数据库任意读写能力 |
| Orchestrator | 计划循环、工具调用、停止策略、降级 | 把模型输出当可靠 SQL |
| 本地小模型 | 语义理解、关键词扩展、候选评分、证据压缩 | 决定访问控制、修改底层权限 |
| SQLite | 可读原文、状态、派生索引、修订关系 | 自动理解复杂模糊语义 |

## 四条核心数据流

### F1. 会话写入

宿主事件 → 去敏/权限检查 → 幂等归档 → SQLite 事务提交 → 可选异步提炼摘要/主题 → 索引更新。**原文提交成功不应依赖本地模型在线。**

### F2. 自动预取

用户消息到达 → 插件按配置调用本地服务判定 `none/recall` → 可能的多轮检索 → 返回最少证据 → 注入当前请求上下文，不无限积累到未来轮次。要核验 DSH 当前版本具体钩子语义及持久化副作用。

### F3. 主 LLM 工具回忆

模型调用 `memory_recall` → MCP/DSH 转换 → 本地服务执行检索循环 → 返回来源和摘要 → 主模型答复。工具失败必须使用结构化错误结果，不能幻造历史。

### F4. 会话重置与恢复

清空主模型会话数据 → 创建新的 conversation_id → 以不变的授权身份访问同一长期数据库 → 查询历史 → 得到证据。注意“清空聊天记录”和“主动要求删除长期记忆”是不同操作，应有明确用户授权语义。

## 硬性设计

- 本地模型调用必须异步/可超时/可取消；Orchestrator 负责控制最大总耗时。
- 同一请求的状态目录 → 候选 → 详情 → 最终摘要，必须独立跟踪 trace_id。
- 不要假定自动预取是无副作用动作：若某版本 DSH hook 追加永久消息，应通过当前版本确认注入行为并验证重复回放处理。
- 运行时与存储必须可脱离 DSH 启动和验证；本地模型供应商应可更换。
- 记忆数据库每次写入可靠先于主动摘要，避免进程崩溃导致未经保存的经历丢失。

## 故障隔离与退路

1. 本地推理不可用 → 基础索引检索 / 无结果返回，不阻断主模型一般回答。
2. SQLite 忙/锁冲突 → 有界重试 + 业务错误；不要无限卡住在线回复。
3. DSH 适配器故障 → 独立 API / MCP 仍可用。
4. MCP Server 中断 → 只影响该调用，主模型可继续处理非个人事实问题。
5. 上下文预算触顶 → 优先保留可核验证据、时间与状态；宁可返回需要进一步检索也不虚构。


## 模型运行模式与数据所有权边界（增补）

- **权威数据**：SQLite 原始授权事件、修正记录；摘要、关键词、状态索引、嵌入、模型输出均可重建。
- **主 LLM**：线上 API（可切换），它只看到经过预算控制的候选证据，不看到整个数据库，也不拥有写入历史的唯一权限。
- **本地模型**：初始 `Qwen3.5-0.8B`，默认 **Non-Thinking**；它一次只能选择受限动作或候选 ID，不执行任意 SQL。它可在 Orchestrator 控制下被多次调用。
- **本地模型服务**：推理后端可更换；是否支持 `enable_thinking`、JSON Schema/约束生成、超时/取消，开发时逐一证明。
- **DSH 插件**：运行于 DSH 宿主的地址空间；MCP 适配器是通信桥梁，宿主需要自行提供可靠的事件采集及受控预取。

### 端到端关键时序

1. 新消息进入宿主；为消息分配来源 ID 与长期 `agent_id`，将获准事件持久归档或进入具备补偿机制的可靠缓冲。
2. 如果配置开启预取，优先使用低成本 gate；有必要时本地小模型 → 状态目录 → SQLite 候选 → 摘要/详情 → 精简证据。
3. 经 DSH 正式支持的钩子把证据加入**本次线上请求**，明确它是否被记录成永久会话消息；同一步骤不重复注入。
4. 主模型可另外显式调用 `memory_recall`，读取更多证据，而不是整个历史。
5. 会话可以重置；只要长期身份与存储保留，新会话还能调用同一个 FishMemory 服务。

**重要部署区别**：如果 DSH 在本机、仅主模型 API 在线，`127.0.0.1` 可用于本地桥接；若 DSH 本身部署在远程主机，`127.0.0.1` 指远程主机自身，必须设计专门的安全网络连接，禁止误把记忆服务开放到公网。
