# 06. 独立 HTTP API、MCP Tool 业务契约（待实现）

> 下面 `POST /v1/...`、字段及枚举是**本项目拟定接口**，不是 MCP/DSH 官方 API。研发时可扩展，但修改必须更新本文和回归测试。

## 设计约定

- 业务 JSON 统一携带 `request_id` / `trace_id` 及授权上下文，身份应由鉴权层确认，不能只信任请求体中的 user_id。
- 时间统一采用带时区的 ISO 8601；内部推荐 UTC。
- 所有成功/失败响应有机器可判状态；不通过编造记忆维持 UI 体验。
- 对 HTTP、MCP、DSH 的适配层保持相同的内部业务语义。
- Tool 的名称、Schema 字段必须短小稳定；主模型不需要知道 SQLite 结构。

## `POST /v1/memory/ingest`（自动事件写入）

**用途**：接受经授权的聊天消息、工具结果或人工导入。应支持批量事件与幂等请求。

请求字段建议：`event_id`（必需幂等键）、`agent_id`、`conversation_id`、`actor_type`、`source_type`、`occurred_at`、`content_text`、`privacy_level`；身份由鉴权上下文确定。可选 `source_ref`、`metadata`。

响应字段建议：`status`（stored/duplicate/rejected）、`event_id`、`index_status`（pending/ready/failed）、`trace_id`。服务成功返回表示**已事务持久化原文**，不能误表示摘要必定构建成功。

## `POST /v1/memory/recall`（唯一必需的主模型可见读工具）

输入字段：

| 字段 | 类型 | 约束 |
|---|---|---|
| `query` | string | 必需；当前待回答的记忆需求 |
| `recent_context` | string 或消息片段 | 可选；严格长度、信任与隐私限制 |
| `agent_id` | string | 必需；服务鉴权范围内 |
| `mode` | enum | `auto` / `explicit`，默认 auto |
| `budget` | object | 可选：线上 Token、迭代数、候选数、截止时间上限 |
| `time_hint` | object | 可选：检索时间区间或“上次”提示，不视为已验证事实 |

输出字段：

| 字段 | 类型 | 约束 |
|---|---|---|
| `status` | enum | `no_memory_needed` / `found` / `partial` / `not_found` / `error` |
| `items` | array | 每项 `memory_id`, `summary`, `event_time`, `source_ids`, `validity`, `epistemic_type` |
| `context_text` | string | 给线上 LLM 的最短记忆片段，受 Token 预算约束 |
| `uncertainty` | string 或 null | 缺证据、冲突或摘要限制的说明 |
| `trace_id` | string | 用于排查，不含私密原文 |
| `metrics` | object | 仅宿主可见，允许包含本地耗时、轮数、查询次数 |

输出 `context_text` 与 `items` 必须基于**同一证据集合**。不能返回无来源的“用户以前说过”。调用者必须能按 ID 请求允许的详情（可单独 internal API）。

## 内部受控读接口（不得直接暴露给主 LLM）

- `POST /internal/memory/search-topics`
- `POST /internal/memory/search-summaries`
- `POST /internal/memory/search-timeline`
- `POST /internal/memory/get-details`

这些只是内部服务设计名称；允许受控 Orchestrator 使用，不能让本地模型请求携带原始 SQL。

## `POST /v1/memory/forget`（高风险管理操作）

要有明确授权主体、目标 `memory_ids` 或有限作用域、删除模式、确认标记、审计记录和可解释的备份删除语义。默认不得作为自主主 LLM 写工具暴露。行为必须满足验证用例：删除后 FTS/摘要/缓存都无法返回目标内容。

## 工具暴露建议

对主 LLM，第一期**只暴露** `memory_recall`；写入由 DSH/宿主的可信事件捕获链完成（避免让模型决定所有历史是否入库）；人工手动录入、编辑、删除通过单独受控 API/UI。未来是否给主模型写工具，应经过权限和评测后决定。

## 自动预取契约

预取与主动 Tool Call 使用同一个 Recall 业务接口。桥接层根据 `status` 决定是否注入；`no_memory_needed` / `not_found` 不应塞入无意义大量文本。相同请求应有内容去重与注入标识，防止循环重入和重复上下文累计。

## 不存在时的行为

- 无数据库：`error`（服务不可用），不声称历史不存在。
- 数据库有效但无匹配：`not_found`。
- 证据不足：`partial`。
- 记忆不必要：`no_memory_needed`。
- 身份不合法：由鉴权拒绝，不能返回其他人的记忆。


## 内部模型编排与模式字段（业务建议，非上游标准）

- `recall` 响应建议单独包含 `retrieval_status`（搜索是否完成）和 `answer_support`（证据是否足够支持线上回答），避免 `found` 与 `partial` 混淆。
- `trace_id` 应贯穿 DSH Hook、MCP Tool、核心编排、本地模型、SQLite 与线上 API 计费记录，且不得默认携带原始隐私文本。
- 记录 `model_profile`（模型 ID/revision/量化/后端）、`thinking_enabled`、`iterations`、`stop_reason` 等内部观测字段；**不要求将这些字段发送给付费线上 LLM**。
- 预取与主动调用应共享证据缓存键（身份 + 查询语义/上下文版本 + 记忆库版本），避免重复返回同一摘要；缓存不得跨用户共享敏感内容。
- `memory_recall` 对主 LLM 可见的 schema 不需要传 `user_id`：优先由宿主鉴权绑定身份，防止主模型传一个字符串就能读他人记录。
- `memory_forget`、`memory_export` 等隐私操作必须使用可信 UI/API 或单独明确授权，默认不作为主模型随意调用的工具。
- 不准要求模型生成/发送 `reasoning_content` 来驱动检索；实际功能依赖受控动作列表和证据返回。

## 2026-10-30 用户新决策与开发状态（优先于本文件旧描述）

依据：用户明确要求由主LLM发起记忆查询，本地小模型只负责查询规划与证据筛选，并已授权开发测试。执行ADR-015：当前默认入口为显式memory_recall，不要求本地模型判断是否需要记忆；自动预取与GATE暂不作为当前路径的功能或验收项。后台授权归档职责不变。

仓库现含可运行的本地检索实验，尚非生产服务；原有“仅规格、无代码”描述为初始包历史状态。实现范围、实际环境、复现命令、测试结果和未完成门禁见 docs/14-本地检索实验.md（docs目录内读者使用同目录14文档）。

### ADR-016实验接口补充

`recall_v2(..., selection='each'|'batch')`是本地Python实验入口，非HTTP/MCP接口，默认CLI尚未切换。逐条模型输出`supports: bool`和`quote: str`，服务校验引用属于当前候选原文；这些字段不代表语义验证完成。最多12候选、4条返回证据、30秒总预算。模型错误时返回`partial`与独立`fallback_candidates`，`items`为空。完整限制见15-宽召回与筛选对照.md。

### ADR-017 与当前本机服务契约

HTTP/MCP 已实现范围以 [16-DSH原生插件集成.md](16-DSH原生插件集成.md) 为准。归档 URL 限制为 loopback origin，并拒绝重定向；maxTextChars 按 Unicode 码点计数。服务连接空闲读取上限 5 秒，已认证请求体超时返回 HTTP 408、`{"status":"error","error":"request_timeout"}`。不完整请求头由 HTTP 服务器关闭连接。此限制不是完整请求总时限。

`POST /v1/forget` 对不存在的 ID 也写入当前配置身份范围的墓碑，防止未来重放重新写入；响应是否曾存在与墓碑建立是不同语义。MCP 不提供遗忘工具。当前 bearer token 为单机授权，不能代替多用户鉴权。字段依据：当前实现 `fishmemory/service.py`、`core.py`；设计决定 ADR-017。

### ADR-018 编号查询策略

HTTP/MCP 工具及响应 schema 不变。含文字加数字编号的查询使用 `literal_identifier_guard` 内部策略：一次本地规划、最多 12 候选、至多一次本地筛选、至多 4 条结果；候选为空时不调用筛选。无编号路径保持既有最多三轮预算。`max_rounds` 是上限，不保证实际用满。模型不可用时 `items=[]`，规则后备候选也经过编号和问题文本过滤，保持未验证语义。内部 trace 的 strategy 字段为项目设计，不是 DSH/MCP 官方字段。

### MCP 调用凭证（ADR-020）
响应新增 provenance：provider=fishmemory、trace_id、response_sha256、audit_logged。摘要算法和失败边界见 ../reports/mcp-audit-20261103.md。此为项目扩展，HTTP 响应未变。


## ADR-021：选定事实写入（项目接口，非宿主官方字段）
MCP 新增 memory_store(content,topic,source_quote,mode=autonomous)，HTTP 对应 Bearer 认证 POST /v1/store；字段长度分别 1..1200、1..100、1..4000，mode 为 explicit 或 autonomous。服务器配置绑定身份。SQLite 事务内写入事件、FTS、来源及模式，提交后返回 persisted=true、status=stored/duplicate、items[0].id、reply_policy 与 provenance。相同身份、正文、主题和引用的精确重试幂等；改写不属于精确重试。墓碑拒绝原 ID 再写。引用来自调用者，不等于宿主已认证原话。失败和拒绝不得视作已保存；日志记录工具和结果 ID，无原文和密钥。AstrBot 原生工具从事件绑定身份，详见 [安装与宿主接入](17-安装与宿主接入.md)。
