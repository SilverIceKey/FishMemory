# 01. 愿景、核心价值和范围边界

## 核心愿景

大肥鱼的**对话**是短命上下文，**记忆**是长期资产。无需长期保持聊天窗口，也不依附于某个云端主模型。任何一次会话结束/清空后，新的会话仍然能按需找回有证据的过去经历。

### 核心商业与工程动机

- 将复杂的历史定位、摘要与候选筛选从收费的线上主 LLM 转给本地运行的超小模型。
- 本地模型多轮处理不产生按 Token 计价的云端调用，但仍存在算力、电力、显存、延迟与维护成本。
- 线上主模型只接收与任务相关的精简证据，不用携带冗长、可能过时的会话摘要。
- 记忆可读可改、可追溯，且能随主模型升级而不损失长期事实。

## 核心成功标准

- 用户随时重置会话，保持同一 `agent_id` / `user_id` 的长期记忆仍可读取。
- 原本需要多千 Tokens 历史上下文的问题，基于本地检索缩短线上记忆输入，且答案正确性不劣于有效对照基线。
- 对没有记忆需求的问题，系统能够选择“不检索”，避免不必要延迟。
- 需要旧事实时能够依据事件时间、来源与修正关系回忆正确版本。
- 切换不同线上主模型时，持久记忆可继续使用，但不保证不同模型输出风格完全一致。

## 不是

- 不以创造生命、证明主观体验为验收条件。
- 不将长期记忆原文装进模型权重或 LoRA。
- 不开发新的通用基础模型作为 MVP 前置条件。
- 不引入重型知识图谱/向量数据库集群作为默认必需依赖。
- 不做必须连接互联网的记忆管理服务。

## 用户故事

1. **回忆**：我问“之前为什么决定放弃方案 A”，系统在新会话找到历史讨论与变更理由。
2. **偏好**：我问“按以前的技术审查习惯评估”，系统找到我同意长期保留的偏好，并以简短要点交给主模型。
3. **会话重置**：原会话被清除，新会话仍可回忆到授权长期保存的内容。
4. **换模型**：从线上模型 X 切换 Y，仍能找到相同历史依据。
5. **修正**：旧偏好被用户更改后，检索默认应用新版本，旧版本只在询问历史时呈现。
6. **隐私与遗忘**：用户明确删除某项记忆，后续任何检索不得再呈现已删除内容或其衍生摘要。
7. **不可知**：如果数据库没有对应记忆，系统返回未找到，不编造“你以前说过”。

## 范围

一期必须：独立服务、SQLite 原文/索引/摘要、事件自动捕获与授权、候选检索、结构化本地模型决策、证据返回、API/MCP/DSH 接入、跨会话持久化、测试与可观测性。

二期可选：向量召回、模型蒸馏/微调、主题层次索引、跨多设备同步、选择性的关系图、记忆质量自修正。是否做由评估数据决定。


## 本次明确的最小产品定位

FishMemory 的**认知能力**是“从当前问题中规划记忆检索”，不是训练出一个保存一生经历的神经主体。完整一生在本项目中的可测试定义是：**长期事件独立落盘、跨会话正确召回、持续修正且有证据、在模型升级后可继续使用**。

本地模型可以多轮工作，但其成本目标是节省**线上付费模型**的处理量；对独立本地部署而言电力/算力不是按 Token 计费，延迟仍有限。默认 Non-Thinking；不以模型产生可见或隐藏的思维链作为必要功能。
