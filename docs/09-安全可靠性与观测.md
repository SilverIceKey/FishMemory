# 09. 安全、隐私、可靠性与可观测性

## 威胁模型与信任边界

用户消息、网页、工具返回、导入历史和本地模型生成内容都可能包含错误或恶意指令。**只有受控服务配置和鉴权结果能决定权限**。本地 0.xB 模型虽然在本机运行，也不是可信数据库管理员。

### 必须防御的风险

| 风险 | 控制 |
|---|---|
| 记忆污染/提示注入 | 对外部内容进行来源标注；检索结果按数据处理；无指令优先级 |
| 跨身份泄露 | tenant/user/agent 由鉴权和服务器强制过滤，不由模型字符串决定 |
| 任意 SQL | 仅允许受控检索操作；不直接执行模型编写的 SQL |
| 错误摘要扩散 | 原文来源可追溯；`inferred` 与 `explicit_user` 必须区分 |
| 误删与删除不彻底 | 明确确认/权限；清理派生索引、缓存和经约束的备份 |
| 敏感信息云端泄露 | 最小披露；必要时脱敏；按隐私标签过滤结果 |
| 重复事件/会话重放 | `event_id` 幂等；来源去重；禁止反复归档同一事件 |
| 模型无限检索 | 总截止时间、步骤数、每步候选与详情大小上限 |
| 归档中断 | 原文提交与索引重建解耦、可重试/恢复 |
| DSH/MCP 兼容断裂 | 锁定版本、合同测试、适配层隔离 |

## 鉴权及访问范围

- 对外访问需鉴权；默认只监听本地回环或受保护网络，不得无认证开放到公网。
- 允许单用户部署，但仍必须区分 `user_id`、`agent_id` 和 `conversation_id`。
- 系统管理员、调用 Agent 与普通用户的权限不同；敏感读写/删除需要更强操作确认。
- API 响应与日志不应该泄露完整原文、凭证、连接密钥和会话 Token。
- 若将来的部署需要多用户，请独立设计和测试实际数据隔离，不要把测试账户共用一份数据库状态当作多租户实现。

## 遗忘和重置的不同语义

- `reset_session`：清空主模型会话上下文/会话历史；**不删除已授权的 FishMemory 长期记忆**。
- `forget_memory`：用户授权删除长期记忆内容及可检索衍生数据。
- `disable_capture`：禁止新事件归档，不等于删除旧内容。
- `delete_account`：按权限清除身份范围内长期数据；具体备份和保留要求须事先说明。

## 故障回退

必须区分：数据库未连接（error）≠ 数据库查不到（not_found）≠ 有候选但证据不足（partial）。任何失败都不应该伪造“过去记忆”。本地模型失败可按需降级到可验证的 SQLite FTS/时间检索；如果依然无法证明则坦承无法确认。主模型通用回答可以继续，但不能杜撰个性化内容。

## 可观测性

每次读取/写入生成 `trace_id`，建议记录：

- `request_type`、`agent_id`（可脱敏）、`conversation_id`（可脱敏）。
- `retrieval_mode`、`gate_decision`、`model_backend`、`model_version`。
- `index_version`、`candidate_count`、`detail_expansions`、`local_iterations`、`stop_reason`。
- `selected_memory_ids`（按权限脱敏）、`source_coverage`、`conflict_detected`。
- `local_input_tokens` / `local_output_tokens`（运行时提供才记录）；`online_input_tokens` / `online_output_tokens`、缓存 Token（供应商支持才记录）。
- `total_latency_ms`、`local_inference_ms`、`sqlite_latency_ms`、`host_latency_ms`、`timeout_reason`。
- 失败回退原因、写事务结果、摘要队列积压/失败。

日志默认不记录完整用户原文；审计日志访问要受权限和保留政策约束。优先使用关联 ID、摘要长度、哈希或脱敏样本。

## 运维基线

- SQLite 备份、恢复演练、数据库完整性校验。
- 迁移前快照与版本控制；不得把 SQLite 文件当普通文本覆盖。
- 监控磁盘占用与索引膨胀；为日志与派生索引设计可清理策略。
- 指定本地推理最大并发，防止 0.xB 模型与系统其他任务抢占资源。


## 运行时失败与 Thinking 防护（增补）

- 若后端未确认接受 `enable_thinking=false` 或同等明确开关，不得仅凭响应看起来短就声称模式已关闭；需要有运行时验证脚本/测试证据（实施阶段提供）。
- 若实验性 Thinking 导致长时间生成、无法终止、重复片段或 token 上限触发，必须安全取消、记录 stop_reason，并回到 Non-Thinking/索引检索路径。
- 本地模型日志和追踪数据不能无策略保存其自由生成的长推理内容。对于涉及隐私的应用应限制记录内容，只保存受控动作、证据 ID、模式与时延。
- 用户请求删除历史时，日志、向量/摘要缓存、临时目录、测试导出和备份都要纳入清理与到期策略。
- SQLite WAL/备份/恢复有独立运维要求；在大规模写入和恢复测试之前，不得以“有 SQLite 文件”冒充完成数据可靠性设计。
