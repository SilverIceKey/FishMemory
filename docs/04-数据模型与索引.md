# 04. SQLite 数据模型与状态感知索引

> 本文是 **FishMemory 业务模式设计**，不是 SQLite/DSH/MCP 官方字段定义。数据库迁移需显式版本管理。

## 设计目标

既要能存十年经历，保持人类可读、可修改、可备份，也要让本地 0.xB 模型在每次请求时只看到**适量的状态目录与候选摘要**，而不是全部历史。

## 建议逻辑实体

### `memory_events`：原始历史事实（真值基础）

| 字段 | 语义 | 约束 |
|---|---|---|
| `event_id` | 全局或作用域内唯一事件 ID | 幂等键，必须唯一 |
| `tenant_id` | 租户隔离 | 单用户部署也保留显式作用域 |
| `user_id` | 数据所属用户 | 不可由模型输出修改 |
| `agent_id` | 大肥鱼等长期代理身份 | 不等同 `conversation_id` |
| `conversation_id` | 本次会话 ID | 重置时变化 |
| `actor_type` | `user` / `assistant` / `tool` / `system` | 内部契约枚举 |
| `content_text` | 原始文本 | 有长度、敏感策略 |
| `source_type` | conversation/tool/import 等 | 可追溯 |
| `source_ref` | 外部源标识 | 不暴露密钥 |
| `occurred_at` | 事件发生时刻 | ISO8601 UTC 推荐 |
| `received_at` | 服务接收时刻 | 区分乱序事件 |
| `privacy_level` | 访问与保留级别 | 不能由无鉴权模型直接修改 |
| `retention_state` | active / excluded / deleted | 删除语义定义见安全文档 |
| `content_hash` | 校验/重复判定 | 不能替代幂等键 |

### `memory_items`：可检索的精炼记忆

| 字段 | 语义 |
|---|---|
| `memory_id` | 逻辑记忆 ID |
| `owner_scope` | 明确 tenant/user/agent 所属范围 |
| `summary_text` | 可读事实摘要，不得凭空补全 |
| `title` | 可阅读标题 |
| `keywords` | 派生标签或关键词（具体表示可采用关联表） |
| `effective_from` / `effective_to` | 知识的有效时间范围 |
| `status` | current / historical / disputed / retracted |
| `epistemic_type` | explicit_user / observed / inferred / imported |
| `evidence_event_ids` | 可反查事件引用（具体可使用关联表） |
| `supersedes_id` | 被新版本取代的记忆 |
| `confidence` | **证据充分性的内部估计**，并非真实概率保证 |
| `summary_model_version` | 生成摘要的本地模型版本 |
| `updated_at` | 最后更新时刻 |

### `memory_state_index`：状态感知总览

这层是本地模型**快速知道数据库里有什么**的关键，但不是把完整存储扫描一遍。

建议维护：`scope`、`topic_id`、`topic_label`、`short_description`、`active_memory_count`、`last_activity_at`、`current_status`、`index_version`。能够快速得到：最近活跃的项目/话题、可能的实体名、重要偏好是否存在、事件时间范围。

要求：状态索引必须按 scope 限定查询，有大小/条数上限；不能每次将完整目录注入小模型。索引可能过时，不能直接当原始事实回答。

### 关系表与操作日志

- `memory_evidence`: `memory_id` ↔ `event_id` 的来源映射。
- `memory_links`: `from_id`、`to_id`、`relation_type`、`evidence_id`，仅用于已具来源的关联。
- `memory_operations`: 记录授权的增、改、删除、合并、重新索引、恢复，敏感字段脱敏。
- `index_jobs`: 派生摘要和索引任务的状态与重试信息。

这些是逻辑实体，最终可以用规范化表、JSON 列等落地，但**不允许丢失来源链、隔离键和修订语义**。

## 索引策略

1. 时间/作用域/事件 ID 使用普通 SQLite 索引。
2. 标题/摘要/关键词可建立 FTS5；针对中文、英文混合内容验证 tokenizer 的实际命中与查询行为。不能假定内置 tokenizer 能满足中文自然语义检索。
3. 对本地小模型先暴露最多 N 个“主题状态 + 摘要候选”，只有在选定 ID 后才读取原文片段。
4. 可选向量索引必须有 embedding_model_version 及重建机制；一期可以不选向量扩展。
5. 全文数据与 FTS/摘要/缓存必须拥有明确的删除传播策略。

## 写事务与一致性

- 原始事件写入成功应以 SQLite 事务提交为准。
- 摘要/索引异步失败不影响已提交原文；需要后台任务可重放。
- 更新偏好不得直接覆盖先前内容而丢失可允许保留的历史证据，需时间有效性与 supersede 关系。
- 明确隐私删除时，按要求真正移除可检索正文、派生摘要和索引，且设计备份的删除保留策略。不能仅标记 deleted 但仍允许还原。
- SQLite 的多进程/线程并发方式与 WAL/备份策略要按部署方式验证；不要凭空承诺多写者高吞吐。

## 查询权限

本地小模型只返回封闭操作集合，如 `search_topics`、`search_summaries`、`get_details`、`search_timeline`、`finish`。所有条件和作用域由受控执行器校验；不提供 `execute_sql` 给主模型或本地模型。


## 状态索引的读取预算及旧数据重构（增补）

- `memory_state_index` 是有限目录，不是可直接断言用户偏好的真值；每个条目应保留生成时间、索引版本、关联源及当前/过期标记。
- `memory_items` 包含摘要的生成模式和模型版本；摘要版本与原文版本可独立重建。
- 同一次记忆查询可先查目录、再查摘要、最后按 `memory_id` 展开原文；**禁止把全部 topics、摘要或原文一开始就塞给本地 0.xB 模型**。
- FTS5 `unicode61` 对中文连续字符的词边界与自然分词需求不等价；如选 `trigram`，必须测试中文三字及以上片段、两字词、短语、LIKE/GLOB、索引大小与延迟，不可把它称作语义向量检索。
- Session 事件必须具有持久来源引用及游标/断点，避免 `session/event` 异步观察者丢失部分事件后无法重新归档。
- 记忆删除/隐私停留影响所有衍生索引，包括缓存、重新导入、评估集副本；需定义备份中保留/清理和恢复策略。
