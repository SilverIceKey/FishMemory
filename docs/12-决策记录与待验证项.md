## 工程性建议（尚未等于用户强制要求）

- 初期模型候选为 Qwen3.5-0.8B 或同级别可用模型，实际质量与延迟用评估决定。
- 初期采用 SQLite FTS5 + 短摘要候选，向量扩展不是必选。
- 面向线上模型只暴露 `memory_recall`，写入和敏感操作由宿主可信链路控制。
- 部署以 Linux 单机优先，Python 核心服务 + 独立 DSH 适配器。
- 默认启用有限轮次检索与超时保护，不允许无限本地模型循环。

## 必须在开发前确认但不能据此编造事实

| 问题 | 影响 | 默认处理建议 |
|---|---|---|
| DSH 锁定版本及其 API 差异 | 插件是否能正确执行/注入 | 先依据官方源码记录版本 |
| 线上 LLM 供应商和 API 计费方式 | 真实费用节省、缓存策略 | 抽象主模型，不预设单一供应商 |
| 本地运行位置与可用 CPU/GPU 资源 | 0.xB 模型吞吐/并发/量化 | 在实际目标机器 benchmark |
| 多用户还是单用户先行 | 鉴权、部署复杂度 | 逻辑隔离从第一天保留；先单人使用可行 |
| 是否保留所有原始会话 | 隐私、存储、导出/删除策略 | 以用户授权、可配置保留为准 |
| 是否引入向量召回 | 模糊查询精度与资源成本 | 先比较 FTS + LLM 与向量方案 |
| 自动预取是否默认启用 | 端到端延迟和意外上下文成本 | 开关 + A/B 性能验证 |
| 事件采集来源哪些可视为可信 | 污染、安全边界 | 先只允许用户对话和可信工具结果 |

### 待验证事项新增

- 实际推理后端如何关闭 Thinking：是否在 OpenAI-compatible `extra_body.enable_thinking=false`、chat template 参数或后端选项上实现，以实测适配器为准；不假定所有后端同一字段。
- 不同量化对 0.8B 中文模糊指代、短 JSON 和排序精度的影响。
- DSH `agent/pre-step` 注入的生命周期和 `session/event` 异步通知的完整性；是否需要补扫 Session 持久事件日志。
- 中文 FTS5 tokenizer 选择是否满足两字短词/同义表达；不满足时是否需要增加向量召回。
- 线上不同计费缓存策略下，自动预取和显式 Tool Call 哪个性价比更高。

## ADR-015（2026-10-30，用户明确决定）

主LLM决定何时调用memory_recall；本地模型在收到请求后只负责查询哪部分记忆、如何补查与筛选证据。当前不实现是否检索的本地门控，自动预取延后。此决策覆盖ADR-007及FR-08/FR-19/FR-23等涉及本地门控或自动预取的当前执行范围；后台授权归档、持久化与身份隔离要求不变。测试主指标改为候选覆盖、给定候选筛选准确率与端到端证据正确率。

用户已授权开发测试，ADR-008的纯文档状态变为历史记录。现阶段为独立本地实验，不宣称完成完整工作包或MVP。详见14-本地检索实验.md。

## ADR-016（2026-10-30，工程实验决定）

依据ADR-015及本地实测，实验比较保留原始查询候选的宽召回、逐条引用判定和批量筛选。新8题中宽召回候选覆盖7/7，但最终准确率3/8及2/8均低于原版4/8，故不替换默认流程，不开展真实记忆自动注入。方案、测试与限制见15-宽召回与筛选对照.md。此决定不更改用户指定的小模型优先路线，也不代表任何模型官方能力结论。

## ADR-017（2026-10-31，工程安全与兼容决定）

依据用户授权复核 DSH 新实现及 AGENTS 本地原始历史边界：归档插件 serviceUrl 只接受 loopback origin（127.0.0.1、localhost、[::1]），禁止 URL 内凭据、路径、查询及片段，HTTP 请求拒绝重定向。maxTextChars 以 Unicode 码点计数，避免切断代理对。HTTP 服务 socket 空闲读取超时为 5 秒，已认证请求体读取超时返回 408/request_timeout；这不是请求整体时限或并发防护。以上均为项目设计，不是 DSH 官方字段或能力。

新增回归与本机 MCP 验证见 [复核报告](../reports/review-20261031.md)。可靠归档的持久队列、来源检查点和补偿重放仍未完成；ADR-016 的质量结论不因接入成功改变。

## ADR-018（2026-10-31，用户授权继续优化后的局部工程决定）

后续 ADR-019（2026-11-03 状态记录）：用户授权补充自然聊天触发规则并要求两个全新 DSH 会话验证。实现 MCP 工具使用时机描述及独立 guidance.js 静态提示插件，仅在当前 scope 可见 memory_recall 时提供使用规则；不注入记忆正文、不自动检索。依据本机 DSH rc.5 systemPrompt.section、tools.get 接口。插件测试通过不等于自然触发验收通过；截至本次同步，因电脑控制未能读取 DSH 聊天界面，两个新会话测试尚未完成。

对包含文字加数字编号的查询，保留原问题字面编号召回，不允许模型主题硬过滤丢失该候选；合并模型扩展候选后限制最多 12 条。进入模型筛选前，排除不含全部编号的文本、仅提问的文本；若候选复述明确引用另一候选的长来源 ID，优先原来源。仍由本地 Non-Thinking 模型规划与筛选，服务不把词法命中当作事实证明。

这是有界、保守的局部规则，并非实体识别或语义证明。无编号查询仍执行原检索流程；ADR-016 的通用质量限制不变。规则可能对多实体、多句答案、日期/版本数字或别名产生漏查。真实来源角色元数据与语义相关性门禁尚未完成。结果见 [编号查询优化](../reports/identifier-optimization.md)。

## ADR-021（2026-11-04，用户要求与工程实现）
主 LLM 选择写入与读取；直接要求“记一下”时调用写入，自主记录持久偏好后正常聊天，不额外确认。未提交不可宣称成功。新 DSH bundle 默认不启用全量归档；已有授权归档保持独立可选。MCP 和 HTTP 共用 SQLite 写入事务及去重。AstrBot 从平台实例、机器人和发送者绑定可信作用域，私聊以外拒绝。其模型地址和凭据由管理员配置，带 Bearer 发现模型；单个 ID 自动选，多 ID 需指定。依据、版本边界及复现见 [接入指南](17-安装与宿主接入.md)。
